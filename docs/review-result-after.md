# ホテルグランドトーヤ 公式サイト改善レビュー

対象:トップページ／客室／温泉(ご宿泊・日帰り入浴)／お料理／館内施設・周辺観光／アクセス／FAQ の7ページ(デスクトップ表示のスクリーンショットに基づく)

> **前提の注記**:本レビューはスクリーンショット(見た目)に基づく評価です。title/meta description/alt属性/canonical/robots.txt/sitemap.xml、実測のCore Web Vitals(LCP・CLS・INP)、コントラスト比の数値、モバイル実機での挙動は、ソースコードや計測ツール(Lighthouse・PageSpeed Insights・axe DevTools等)での確認が別途必要です。該当箇所は「要ソース確認」と明記しています。

## 1. UI/UXレビュー

### 第一印象

| 観点 | 評価 | 所見 |
|---|---|---|
| 高級感 | ★★★☆☆ | 紺(#16283A)×テラコッタ(#A24730)×生成り色の配色、セリフ体の見出しは上品。一方でトップのファーストビュー写真(夕景の外観)は良いが、客室・館内の写真がスナップ写真的で高級感を下げている |
| 清潔感 | ★★★☆☆ | 余白は十分あるが、客室写真の照明(蛍光灯)やアングルが古い旅館サイトの印象を与える |
| 信頼感 | ★★☆☆☆ | 電話番号・住所はあるが、Google口コミへの導線、受賞歴、第三者評価が見当たらない |
| 老舗らしさ・温泉旅館らしさ | ★★★★☆ | 「湖」「泉」「膳」「館」などの一文字漢字アイコン、和のセリフ体の使い方は世界観として良い |
| 写真の魅力 | ★★☆☆☆ | 花火・湖・外観の写真は魅力的だが、客室・お料理・館内施設の写真の質にばらつきが大きい(下記参照) |
| 行ってみたいと思えるか | ★★★☆☆ | コンセプト訴求(コピー)は良質。ただし決め手になる高解像度・統一感のある写真が不足 |

**問題点**:客室(image 6)・館内施設(image 3)の写真は解像度が低く、構図もまちまち。トップページの花火・湖の写真とのクオリティ差が激しく、サイト全体の「格」がちぐはぐに見える。

**根拠**:トップページのヒーロー画像や「アクセス・周辺観光」下部の花火・ひまわり畑の写真は明らかにプロ撮影・ドローン撮影のクオリティだが、客室ページの室内写真はスマホ撮影に近い画質・構図。

**改善案**:客室・お料理・館内施設は、①同一機材・同一時間帯(自然光)での撮り直し、②最低でも1タイプ3〜5枚(全景・ディテール・眺望)に統一、③現像トーンを揃える(色温度・彩度)。

**優先度**:高

**期待効果**:第一印象での離脱率低下、宿泊単価の高いプランへの誘導力向上。

### デザイン

**問題点**:
1. ヘッダーが**トップページとその他ページで表示内容が異なる**(トップは「JP EN ZH KO」の言語スイッチャーが横並びで見えるが、下層ページは丸い「JP」バッジのみで多言語切替が見えづらい)。
2. アクセスページの地図直下、店名表示エリアに「-」とだけ表示された空白ラベルが見える(image 1)。中身が入っていないプレースホルダーの可能性。
3. ボタンの色は基本テラコッタ(#A24730)で統一されているが、客室ページのフロア別予約ボタンだけオレンジ(#C2622B)と別トーンになっている(直近の実装分)。

**根拠**:image 7(トップ)とimage 1〜6(下層)のヘッダー部分を比較すると、言語スイッチャーの見え方が明確に異なる。

**改善案**:
1. 全ページで同一のヘッダーコンポーネントを使う(言語スイッチャーの表示ロジックを統一)。
2. アクセスページの地図の空白ラベルを確認・削除、または正しい店名を表示。
3. 予約ボタンの色をサイト全体のアクセントカラー(#A24730)に統一し、ボタンごとの独自色を廃止(視覚的な一貫性・ブランド認知のため)。

**優先度**:中

**期待効果**:ブランドの一貫性向上、多言語対応がわかりやすくなることでインバウンド離脱率低下。

### レイアウト

**重大な問題点**:
1. **お料理ページ(image 2)**:「お食事会場」セクションの「お部屋食」「広間会食場」で、見出しの下に画像が表示されるはずの領域が**大きく空白**になっている(テキストのみ表示され、画像が欠落)。
2. **館内施設ページ(image 3)**:「周辺観光」セクションの多くのカード(イルミネーション、レンタサイクル、サイクル区間案内など)が**タイトル・説明文・画像すべて空白のグレーカード**のまま表示されている。これは実装バグまたはCMSデータ未投入の状態で、公開してはいけないレベルの不具合。

**根拠**:image 2の「お食事会場」見出し直下、約400px相当の空白領域。image 3の周辺観光カードのうち約8割が空のプレースホルダーのまま。

**改善案**:
1. お料理ページの`diningVenues.inRoom.image` / `diningVenues.hall.image`が正しく設定・参照されているか確認(パス誤り、フィールド未入力の可能性)。
2. 館内施設ページの`activitiesSection.items`にコンテンツ(name/description/image)がすべて投入されているかCMS側を確認。表示ロジック自体は動いているので、データ未投入が濃厚。

**優先度**:**最高(公開前に必ず修正)**

**期待効果**:これを放置すると「工事中のサイト」に見え、信頼を大きく損なう。修正だけで直帰率・信頼感が大きく改善する。

### CTA(予約導線)

**問題点**:
- 「ご予約はこちら」ボタンの`href`が複数箇所で`#`のプレースホルダーのまま(客室ページのフロア別ボタン、トップページ末尾CTA)。実際の予約システム(じゃらん・楽天トラベル・自社エンジン等)へのリンクが未設定。
- ヘッダーの電話CTA(`tel:`リンク)はドロワー内にあるが、**デスクトップの常時表示ヘッダーには電話番号が見えない**。宿泊予約検討中の離脱防止としては、スクロールしても常に電話番号が見える設計の方が強い。
- 空室検索(カレンダー形式の日付・人数選択)がサイト内に存在せず、外部予約サイトへの単純リンクのみと推測される。

**根拠**:各ページのCTAボタンの`href="#"`実装(前回までの会話で確認済み)。

**改善案**:全予約ボタンに実際の予約ページURLを設定。デスクトップヘッダーに電話番号を常時表示(特に50代以上の宿泊層は電話予約比率が高い)。可能であれば空室検索ウィジェット(外部予約システムの埋め込み)をトップ・客室ページに設置。

**優先度**:高

**期待効果**:予約導線の断絶解消は直接的にコンバージョン率(CVR)に影響。

## 2. モバイルUX

**要確認事項**:提供されたスクリーンショットはすべてデスクトップ幅(約1440px)のため、実機でのモバイル表示は確認できていません。以下はデスクトップの実装(レスポンシブクラスの使用)から推測される論点です。

| 項目 | 所見 |
|---|---|
| ボタンサイズ | Tailwindの`py-3`〜`py-3.5`程度のボタンが多く、44px以上のタップ領域を満たしているか要実機確認 |
| メニュー | ドロワー形式のハンバーガーメニューは実装済みで、モバイルに適した設計 |
| 電話ボタン | ドロワー内に電話アイコンあり。モバイルではこれがCVRの生命線になるため、**ドロワーを開かなくても常時タップできる位置**(画面下部固定バーなど)への追加を推奨 |
| GoogleMap | 埋め込みiframeがモバイルでピンチ操作を阻害しないか要確認(スクロール誤操作の原因になりやすい) |
| ファーストビュー | トップページのヒーロー画像はモバイルでも縦長クロップで魅力を保てるか要確認(横長構図の写真が多いため、スマホでは主要被写体が見切れるリスク) |

**優先度**:中(実機確認後に高になりうる)

**改善案**:実機(iPhone SE相当の小型画面を含む)でのスクリーンショット取得・Lighthouseのモバイルスコア計測を推奨。

## 3. SEOレビュー

### 基本(要ソース確認)

title・meta description・h1〜h3・alt属性・canonical・robots・sitemapは、スクリーンショットからは確認できません。`view-source:`または`curl`でHTMLを取得し、以下の観点で確認することを推奨します。

- 各ページのtitleに「洞爺湖 温泉 宿泊」等の地域+業態キーワードが入っているか
- meta descriptionが120〜160文字程度で要約されているか
- h1がページに1つだけか(PageHeroBandコンポーネントの`pageTitle`がh1として出力されているか要確認)
- 客室・料理・施設の画像すべてにalt属性があるか(コンポーネント上は`alt`propsを渡す設計になっているため、データ側の未入力がないかが論点)

### コンテンツ

現状のページ構成(客室・温泉・お料理・館内施設・アクセス・FAQ)は基本的な検索キーワードをカバーしていますが、以下が弱い、または存在しません。

| キーワード領域 | 現状 |
|---|---|
| 花火大会(洞爺湖ロングラン花火大会) | 客室ページ・トップページに言及あり。しかし「花火大会 日程」「花火 見える宿」などの検索意図に応える専用コンテンツがない |
| 温泉の効能 | 温泉ページ内にあるが、単独の詳細記事にはなっていない(検索流入を狙うなら独立ページ化が有効) |
| 周辺観光・モデルコース | 「周辺観光」セクションはあるが、「洞爺湖 1泊2日 モデルコース」のような具体的な検索意図に応えるコンテンツがない |
| 冬季の楽しみ方 | 見当たらない。積雪期の運転・イルミネーション等の情報が薄い |
| ブログ・お知らせ | 見当たらない。更新性のあるコンテンツが無いと、Googleからの再クロール頻度・新規キーワード獲得機会が乏しくなる |

### 新規作成すべきページ(優先順)

1. **洞爺湖ロングラン花火大会 特集ページ**(季節性の高い検索需要、客室の予約後押しにも直結)
2. **モデルコース・周辺観光ガイド**(滞在時間の想起を助け、宿泊日数増にも寄与)
3. **温泉の効能・泉質詳細ページ**(健康・美容系キーワードでの流入)
4. **FAQ拡充**(今はカテゴリ7種・各5問前後だが、実際の予約前後の疑問(荷物predeposit、送迎の有無等)をさらに拡充)
5. **お知らせ・ブログ**(季節メニュー、イベント、休館情報等)

**優先度**:中〜高(花火特集は季節性があるため高)

### 内部リンク

各ページ末尾の「あわせてご覧ください」(関連リンク)は良い実装。ただし、**本文中(段落内)からの関連ページへのリンクがほぼ無い**(例:お料理ページの「地元食材」という記述からアクセスページや周辺観光への言及リンクがない)。文中リンクを増やすことで回遊性とSEO内部リンク評価の両方が向上します。

**優先度**:低〜中

## 4. Core Web Vitals(要実測)

スクリーンショットからは数値計測ができないため、以下は実装から推測される**リスク要因**です。実際はPageSpeed Insights/Lighthouseでの計測を強く推奨します。

| 指標 | リスク要因(推測) | 改善案 |
|---|---|---|
| LCP | トップページのヒーロー画像が大きい単一画像で、`loading="lazy"`をヒーロー画像に誤って適用していないか要確認(ヒーローは**lazyにしてはいけない**、逆に`fetchpriority="high"`を付けるべき) | ヒーロー画像はWebP/AVIF化+`fetchpriority="high"`、他の画像は`loading="lazy"`のままでよい(客室ページ等は既にlazy実装済みと推測) |
| CLS | 画像に`width`/`height`(またはaspect-ratio指定のCSS)が無いと、読み込み中にレイアウトが動く。客室ページの`aspect-[4/3]`等のクラス指定は良い実践 | 全画像コンポーネントで`aspect-ratio`指定を徹底(既にTailwindの`aspect-[4/3]`等で一部実装されているのは良い) |
| INP | ドロワーメニュー・検索モーダルなどReactコンポーネントの`client:load`指定が多いと、初期JS実行負荷が上がる可能性 | Astroの`client:idle`や`client:visible`に変更できる非重要コンポーネント(検索アイコン等、必須動線でないもの)がないか見直す |
| 画像形式 | 現状`.jpg`/`.png`の直参照が多い(`/assets/photos/xxx.jpg`) | WebP(可能ならAVIF)への変換、Astroの`<Image>`コンポーネントによる自動最適化・レスポンシブ画像化を推奨 |
| 圧縮・キャッシュ | S3配信予定とのことなので、CloudFront等のCDNを併用し、`Cache-Control`ヘッダーを画像・静的アセットに長期設定することを推奨 |

**優先度**:高(特に画像最適化とヒーロー画像のLCP対策)

**期待効果**:表示速度改善は直帰率低下・SEO評価向上・モバイル体験向上に直結。

## 5. アクセシビリティ(要ツール確認)

WCAGの数値基準(コントラスト比4.5:1以上等)は目視では正確に判定できないため、axe DevTools等でのチェックを推奨した上で、目視での懸念点を記載します。

| 項目 | 所見 |
|---|---|
| コントラスト | 本文の`#55524C`(グレー系)と背景`#FAFAFA`/白の組み合わせは、小さい文字サイズ(0.78rem前後)では**コントラスト不足の懸念**あり。要ツール確認 |
| alt属性 | コンポーネント上はprops設計されているが、データ未入力の画像がないか(特に館内施設ページの空白カード群は画像自体が存在しないため、alt云々の前に**コンテンツの欠落**が優先課題) |
| フォーカス | ボタン・リンクに独自の`focus`スタイル(`focus:outline-none`等)が見当たらない実装があれば、キーボード操作時にフォーカス位置が視認できないリスク |
| フォーム | FAQページのアコーディオン(+ボタン)がキーボード(Tab/Enter)で開閉可能か要確認。予約フォームがあれば、エラー表示・ラベルの`for`/`id`紐付けも要確認 |
| スクリーンリーダー | アイコンのみのボタン(検索アイコン、メニュー開閉、地図操作アイコン等)に`aria-label`が付与されているかが鍵。検索アイコンは実装確認済み(`aria-label={searchOpenLabel}`) |

**優先度**:中

## 10. コンバージョン改善(CRO)

| 項目 | 状況・改善案 |

| CTA位置 | 各ページ末尾のみで、**ページ中間(スクロール中)にCTAが出現しない**。長い客室ページ・温泉ページでは、フロートボタン(画面下部固定の「予約する」ボタン)の追加を推奨 |
